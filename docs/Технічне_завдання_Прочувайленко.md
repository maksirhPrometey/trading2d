**1\. ЗАГАЛЬНІ ПОЛОЖЕННЯ ТА ТЕРМІНОЛОГІЯ**

Це Технічне завдання (далі — ТЗ) є невід'ємною частиною Договору та визначає вимоги до функціоналу, структури, дизайну та технічних характеристик Інтернет-магазину.  
З метою уникнення розбіжностей під час приймання-передачі виконаних робіт, Сторони погодили єдиний критерій готовності для кожного елемента, модуля або системи в цілому:  
**Визначення поняття «ГОТОВО» («Прийнято»):** Елемент, функціональний модуль або сторінка вважаються готовими виключно тоді, коли вони повноцінно несуть свій закладений функціонал, працюють без критичних помилок (помилок типу Fatal Error, 404, 500), повністю відповідають вимогам цього ТЗ, коректно відображаються на узгоджених типах пристроїв (десктоп, планшет, мобільний) та проходять повний цикл користувацького сценарію без збоїв.

**2\. ЗАГАЛЬНІ ТЕХНІЧНІ ВИМОГИ**

Для того, щоб система вважалася готовою, вона повинна відповідати таким загальним технічним параметрам:  
**2.1. Технологічний стек:** Розробка виконується на чистому коді (Фронтенд — HTML, CSS, JS, HTMX; Бекенд — Python/Django).

**2.2. Адаптивність:** Коректне відображення на мобільних пристроях (від 320px), планшетах та десктопах (до 1920px). Елементи не повинні перекривати один одного або виходити за межі екрана.

**2.3. Кросбраузерність:** Стабільна робота в останніх актуальних версіях браузерів: Google Chrome, Apple Safari, Mozilla Firefox, Microsoft Edge.

**2.4. Швидкість завантаження:** Показник Performance в Google PageSpeed Insights повинен бути не менше 75 балів для мобільних пристроїв та не менше 85 балів для десктопів (показники гарантуються для базового коду Сайту до моменту встановлення важких сторонніх скриптів Замовника, за умови використання зображень у форматі WebP/JPEG вагою не більше 500 Кб).

**2.5. Базова технічна SEO-підготовка:** Налаштування автоматичного формування файлів sitemap.xml та robots.txt, підтримка ЧПУ (людино-зрозумілих URL), наявність полів для введення мета-тегів (Title, Description, H1).

**2.6. Безпека:** Робота сайту по протоколу HTTPS. Захист відкритих форм зворотного зв'язку від спаму (наприклад, Google reCAPTCHA).

Відображення списку товарів (сітка/список), хлібних крихт (breadcrumbs), блоку фільтрації та сортування. Пагінація або кнопка «Показати ще».

**Картка товару**

Галерея зображень, назва, артикул, статус наявності, ціна, блок характеристик, опис, кнопка «До кошика».

Фотографії гортаються. При зміні модифікації (колір/розмір) змінюється ціна та артикул. Кнопка додає товар у кошик.

**Кошик (Popup / Сторінка)**

Список товарів із мініатюрами, модифікаціями, полем кількості, кнопкою видалення та загальною сумою.

**Оформлення (Checkout)**

Форма введення даних покупця, вибір способу доставки та оплати, блок підтвердження замовлення.

Валідація полів працює. Замовлення записується в БД, створюється в адмінці, клієнту та менеджеру надходить сповіщення.

**Інформаційні сторінки**

«Про нас», «Доставка і оплата», «Договір оферти», «Політика конфіденційності».

Текст коректно форматується, форми зворотного зв'язку працюють.

**4\. ІНТЕГРАЦІЇ ТА ПЛАТІЖНІ МОДУЛІ**

**4.1. Модуль доставки (API логістичних компаній, напр. UPS, DHL, Nova Poshta):**

**Функціонал:** Автоматичне завантаження міст та відділень через API.

**Критерій «Готово»:** Користувач може обрати відділення зі списку. Дані коректно передаються в панель адміністратора.

**4.2. Модуль онлайн-оплати (напр. Stripe, PayPal, WayForPay):**

**Функціонал:** Переадресація на захищену сторінку платіжного шлюзу.

**Критерій «Готово»:** Після успішної оплати статус замовлення в адмінці автоматично змінюється на «Оплачено», користувач бачить сторінку подяки. При помилці — статус «Очікує оплати».

**4.3. Обробка даних (GDPR):**

Форми збору даних (Checkout, контакти) обов'язково містять чекбокс згоди користувача на обробку персональних даних.

**4.4. Доступи:**

Інтеграція зовнішніх сервісів здійснюється виключно за умови своєчасного надання Замовником усіх доступів, API-ключів та зареєстрованих мерчант-акаунтів.

**5\. ПАНЕЛЬ АДМІНІСТРАТОРА (CMS / АДМІНКА)**

Панель адміністратора вважається готовою та працездатною, якщо виконуються такі вимоги:  
**5.1. Управління каталогом:** Можливість додавати, редагувати, видаляти категорії та товари. Завантаження фото, керування цінами, статусами наявності.  
**Критерій «Готово»:** Будь-які зміни, внесені в адмінці, відображаються на клієнтській частині сайту протягом 1 хвилини (з урахуванням кешування).

**5.2. Управління замовленнями:** Перегляд списку замовлень, детальна інформація про клієнта та товари, зміна статусів («Нове», «В обробці», «Відправлено», «Виконано»).  
**Критерій «Готово»:** Статуси змінюються без збоїв, менеджери мають доступ до повної інформації про замовлення.

**5.3. Управління локалізацією:** Можливість додавати/редагувати переклади для товарів та інтерфейсу узгодженими мовами.
